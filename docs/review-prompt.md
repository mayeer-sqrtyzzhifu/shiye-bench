## 需要你独立判断的六件事

### 1. 判据实现有没有 bug

重点看 `shiye-bench/checks/memory.py`。这个文件里已经出过**四类**判分 bug：

- 中文否认说法（「记不清」「说不清」）没被识别为诚实弃答
- 中文数字（「三十四」）不匹配 expect 里的 `34`
- 禁词与期望词重叠（「不去」既含「去」又被判编造，得出「命中 + 编造」的矛盾判定）
- `cohen_kappa` 在两次全判否时返回 1.0，把「从不触发」误报成「完美可靠」

**请自己构造边界输入去试**，尤其：
`checks/memory.py`、`checks/rules.py`（`two_part_template` / `formulaic_fragments` /
`check_invented_life` / `session_findings`）、`checks/arcs.py`。

### 2. 统计结论站不站得住

`docs/measurement.md` 定了四条硬规则：**配对 + n≥240 + 每用例≥3 次采样 + 符号检验 p<0.05**。

请逐个核对 `docs/findings.md` 里 F1–F9 的「验证方式」是否符合这四条。
特别检查：

- F2 的证据是 10 条用例（n=10），符号检验要 6:0 才显著，够吗？
- F4 用的是整版人格对照，240 条 × 3 次，这条最扎实，也请复核
- F5/F6 被判「实测无效」并已回滚，回滚是否彻底（代码里还有没有残留）

**如果发现某条结论的证据强度与它的状态标签不符，直接指出来。**

### 3. 测量模型本身对不对

`docs/measurement.md` 的核心论断是「同一个输入，生成结果是随机的，
温度降到 0 也复现不了（12/12 全不同）」。这支撑了「只看分布、不看单条」的方法论。

请判断：
- 这个论断的实验设计（`run_noise.py`）有没有漏洞
- 由它推出的「n=240、k=3 才够看 6–8pp」是不是合理
- `checks/variance.py` 的方差分解公式有没有用错

### 4. 判官（LLM 评委）可信吗

`judge/l2.py` 的默认问法换过一次：从「是否承接情绪（而不是马上给建议）」
改成「是否回应了用户说到的具体内容」。理由写在注释里。

请判断：
- 换问法这个决策有没有把问题从「同义反复」变成另一种偏差
- `judge/pairwise.py` 的换位一致性检验（25%–50% 反转）是否足以否掉成对判据
- `run_judge_questions.py` 用「真人咨询师得分应≥40%」作为判据是否合理

### 5. 有没有**没被发现的**作弊路径

这是最需要外部视角的地方。项目已经吃过一次：
为了让问句率达标改了人格，结果长出新公式「你是想让我听着，还是一起捋捋」。

请想：**如果我要让这套 benchmark 的所有指标都变好，同时让体验变差，怎么做？**
列出你能想到的路径，并检查现有守卫（`session_findings`、`formulaic_fragments`、
`check_invented_life`、危机用例）能不能拦住。

### 6. 产品侧代码

`shiye/src/companion/` 里有几处是「知道有问题但没修」的：

- `recall.py`：指代式提问靠「最近记忆兜底」，语义相近但无共同字的提问（如问「兄弟姐妹」
  而记忆里是「独生女」）召回为空
- 记忆是**追加式碎片**，同一槽位的新值不覆盖旧值（改期/改主意后会答旧值）

请判断这两条描述是否准确，以及是否有更简单的修法被忽略了。

## 你可以运行什么

**零成本、随便跑：**

```powershell
# 两个仓库的单元测试
python -m pytest -q                      # 在各自目录下

# 判据自检：变形测试（不需要模型）
python run_metamorphic.py                # shiye-bench 下

# 用已有运行结果重算，不调用模型
python scripts/reanalyze.py
python run_metrics_audit.py              # 指标体检
```

**会花钱、请克制：**

任何 `--provider real` 的命令都会调用 DeepSeek API（密钥在环境变量
`COMPANION_API_KEY`，`.env.example` 里写了变量名）。
单次调用约 3 秒。**建议不要跑超过 60 条用例的实验**，
否则一边 review 一边烧钱，而且结果本身噪声很大。

要跑就选最便宜的：

```powershell
python run.py --provider real --limit 12 --workers 4
```

## 一些背景，避免你重复踩坑

- 这个项目的文档里**保留了大量自我否定**（F5/F6 被判无效并回滚、F2 的「有害」结论
