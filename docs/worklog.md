### 关键发现

#### SmileChat（CC0）

```
仓库总文件    55,165 个对话
采样 120 段 → 1,375 轮
每段轮数      中位 12（最短 2，最长 22）
client 长度   中位 39 字（P90 92，最长 483）
counselor 长度 中位 91 字（P90 185，最长 1162）
角色均衡      client 695 / counselor 680
```

三个判断：

1. **策略标注是空的**——4,073 条 annotation，有内容的 **0 条**。
   README 里没提标注，实测确认不可用。
2. **咨询师回复是来访者的 2.3 倍长**，中位 91 字。
   这与我们要的"10–50 字、不解释、不总结"正相反，
   **不能当风格参照**，只能当"另一种风格"的对照。
3. **95% 的开场带问号**——是求助式开场（"能给我一些建议么？"），
   不是日常闲聊（"今天好累"）。

结论：SmileChat 的价值**在来访者那一侧的真实中文情绪表达**，不在对话结构。

#### PsyQA（需申请，但示例可看）

示例 100 条，268 个答案，**888 个策略标注片段**，每答案平均 3.3 段。
标注格式是按字符区间打标：

```json
{"start": 0, "end": 78, "type": "Interpretation"}
```

类型分布：

| 策略 | 占比 |
|---|---|
| Interpretation（解释） | 47.9% |
| Direct Guidance（直接指导） | 33.2% |
| Others | 7.4% |
| Approval and Reassurance（认可安抚） | 5.2% |
| Self-disclosure（自我披露） | 2.3% |
| Restatement（复述） | 2.1% |
| Information（信息） | 1.9% |

**这组数字本身就是个发现**：心理咨询里 81% 是"解释 + 指导"，
而认可与复述只占 7%。**陪伴正好相反**——我们的人格要求"少给建议、多认可"。

也就是说：**咨询语料的策略分布，恰好是陪伴 agent 要避免的分布**。
这条应该写进 benchmark 的判据说明里，否则很容易照着咨询语料调参，
把 agent 调成一个小咨询师。

### 决策

| 决策 | 理由 |
|---|---|
| 用 SmileChat 的 **client 轮**做输入素材 | 真实、CC0、量足够 |
| 不用 counselor 轮做风格参照 | 长度和策略分布都与目标人格相反 |
| 策略分类用 **PsyQA 的 7 类**（而非 ESConv 的 8 类） | 中文场景，且已确认标注真实存在 |
| PsyQA 全量**暂不申请** | 示例已够定分类体系；等真需要训练数据再说 |

### 追加：跑通第一份真实评测

把「能跑」这件事做实了。链路：

```
SmileChat client 轮
   → 采样成单轮用例（固定 seed）
   → shiye 库模式跑一轮（独立临时库）
   → L1 规则判定
   → markdown 报告
```

首轮真实结果（12 条）：

```
平均长度   41.5 / 38.6 字（两次运行）
平均问句   0.25 / 0.17
语气词开头  0/12 → 1/12
规则命中   1 次（too_long）
```

**结论：结构指标全部落在人格声明的区间内**（长度 10–60、问句 ≤1、不以语气词开头）。

过程中发现并修掉三个问题：

| 问题 | 修法 |
|---|---|
| 采样到大量收尾致谢句（"非常感谢您的鼓励"） | 排除致谢正则 + 只取开场轮 |
| 中间轮次依赖前文，单拎出来驴唇不对马嘴 | 单轮用例只取每段的前 3 轮里的来访者发言 |
| 标注器「其他」占 42% | 补问句句式（无问号问句）+ 新增「解释」类 |

### 一个值得记的信号：解释占比

补完分类后，12 条回复的分布：

| 策略 | 条数 |
|---|---|
| 提问 | 5 |
| **解释** | **4** |
| 反映 | 2 |
| 其他 | 1 |

「解释」占到三分之一。而 PsyQA 的统计里，解释占咨询语料的 **47.9%**，
认可与复述只占 7%。

**假设**：人格里那句"给情绪命名"会把 agent 推向咨询师式回应。
这不是错，但它是个可测的倾向——**「解释占比」应该成为 benchmark 的固定指标**，
用来观察 agent 有没有从"陪伴"漂向"咨询"。
